# 全唐诗检索 — 生产部署手册（tp.textengine.cn）

面向 **零基础**：按顺序复制命令执行即可。  
目标：在腾讯云 **43.142.176.9**（与清嘉录同机）上线 **https://tp.textengine.cn**。

---

## 你将得到什么

- 浏览器打开 `https://tp.textengine.cn` 可检索全唐诗（约 4.1 万条索引）
- 清嘉录 `https://qjl.textengine.cn` **不受影响**
- 数据在数据盘 `/data/qts/`，代码在 `/opt/quatangshi`

## 一、准备清单（动手前勾选）

| 项 | 说明 |
|----|------|
| ☐ 域名权限 | 能登录 `textengine.cn` 的 DNS 控制台 |
| ☐ 服务器登录 | 能用 **`ssh ubuntu@43.142.176.9`** 登录（腾讯云 Ubuntu 默认禁用 root 直连，属正常） |
| ☐ 443 入口 | 已知本机谁监听 443，并愿为 `tp` 增加反代（第十一节，一次性） |
| ☐ GitHub 仓库 | 代码在 https://github.com/cobrayao-blip/Suzhou-in-Tang-Poetry- |
| ☐ 约 30–60 分钟 | 首次构建镜像 + 导入索引 |

**密码本**：准备两个小本本，分别记下（不要发给他人）：

1. `POSTGRES_PASSWORD`（PostgreSQL）
2. `MEILI_MASTER_KEY`（Meilisearch，建议 32 位以上随机字母数字）

可用 PowerShell 生成随机串：

```powershell
-join ((48..57 + 65..90 + 97..122) | Get-Random -Count 32 | ForEach-Object {[char]$_})
```

## 二、配置域名 DNS

1. 登录购买 `textengine.cn` 的域名服务商（腾讯云 DNSPod 等）。
2. 添加 **A 记录**：

| 主机记录 | 记录类型 | 记录值 |
|----------|----------|--------|
| `tp` | A | `43.142.176.9` |

3. 保存后等待 **5–30 分钟** 生效（部分地区更久）。

**检查（在你自己电脑上，可选）：**

```powershell
nslookup tp.textengine.cn
```

应看到地址 `43.142.176.9`（未生效时先继续后面步骤，最后再测网站）。

## 三、用 SSH 登录服务器（Windows）

### 3.1 打开终端

- 按 `Win + R`，输入 `powershell`，回车。

### 3.2 登录（用 ubuntu，不要用 root）

```powershell
ssh ubuntu@43.142.176.9
```

- 第一次会问 `Are you sure you want to continue connecting?`，输入 `yes` 回车。
- 按提示输入 **ubuntu 用户密码**（或密钥 passphrase；输入时屏幕不显示字符，属正常）。

登录成功后，提示符类似 **`ubuntu@VM-xxx:~$`**，表示已在服务器上。

> **`ssh root@43.142.176.9` 连不上是正常的**：腾讯云 Ubuntu 镜像默认关闭 root 密码登录，请始终用 **ubuntu**，需要管理员权限时在命令前加 **`sudo`**（见下一节）。  
> 密钥登录示例：`ssh -i C:\path\to\your.pem ubuntu@43.142.176.9`

### 3.3 关于 sudo（必读）

本手册中，凡需要创建 `/data`、`/opt`、安装软件、运行 Docker 的命令，均已写上 **`sudo`**。  
执行后若提示输入密码，填 **ubuntu 用户的密码**（不是 root 密码）。

验证 sudo 是否可用：

```bash
sudo whoami
```

应输出 `root`。

（可选）若希望以后不用每次加 `sudo docker`，可执行一次 `sudo usermod -aG docker ubuntu`，然后 **断开 SSH 重新登录**；本手册为省事仍统一写 `sudo docker`。

## 四、服务器：挂载数据盘与目录

以下命令均在 **SSH 里**执行（服务器上），需要权限处已加 `sudo`。

### 4.1 查看磁盘

```bash
lsblk
df -h
```

确认有 **约 60G 的数据盘**（常见设备名 `vdb`，挂载点 `/data`）。  
若尚无 `/data`，需先在腾讯云控制台挂载并格式化（仅新机需要；清嘉录若已用 `/data`，可跳过格式化）。

### 4.2 创建全唐诗目录

```bash
sudo mkdir -p /data/qts/pgdata /data/qts/meili
sudo mkdir -p /opt/quatangshi
sudo chown ubuntu:ubuntu /opt/quatangshi
```

### 4.3 PostgreSQL 数据目录权限

```bash
sudo chown -R 70:70 /data/qts/pgdata
```

（PostgreSQL 官方镜像内用户 UID 为 70。）

## 五、安装 Git（若尚未安装）

```bash
sudo apt-get update
sudo apt-get install -y git
git --version
```

### 5.1 测试 GitHub 连接（`git clone` / `git pull` 前必做）

在服务器 SSH 里逐条执行。任一条**长时间无响应或报错**，说明当前网络尚不可用，**稍后再试**，不要反复 `clone` 清空目录。

```bash
# 1）DNS 能否解析
nslookup github.com

# 2）HTTPS 能否连上（15 秒超时）
curl -I --connect-timeout 15 https://github.com

# 3）能否访问本仓库（只测读，不克隆）
GIT_TERMINAL_PROMPT=0 git ls-remote https://github.com/cobrayao-blip/Suzhou-in-Tang-Poetry-.git HEAD
```

**正常时大致会看到：**

- `nslookup`：有 `43.x.x.x` 等地址  
- `curl`：第一行含 `HTTP/2 200` 或 `HTTP/1.1 301`  
- `git ls-remote`：一行以 `commit号` + `HEAD` 结尾  

仍失败时可加大 git 缓冲后再测第 3 条（不保证）：

```bash
git config --global http.postBuffer 524288000
git config --global http.version HTTP/1.1
GIT_TERMINAL_PROMPT=0 git ls-remote https://github.com/cobrayao-blip/Suzhou-in-Tang-Poetry-.git HEAD
```

第 3 条成功后再做下面的 `git clone` 或 `git pull`。

## 十一、域名、SSL 与边缘反代（一次性）

### 11.0 结构说明（请先读）

- **本仓库只负责全唐诗**：Docker、`127.0.0.1:18080`、语料与索引。  
- **`tp.textengine.cn` 与 `qjl.textengine.cn` 是两个产品入口**，不是要把两个项目代码写进同一个 Git 仓库。  
- 公网 **443** 由服务器上「边缘反代」统一处理；配置放在 **`deploy/server/`**（中性文件名，不含其他项目名）。  
- **以后更新全唐诗**：只在 `/opt/quatangshi` 里 `git pull` + 重建 Docker（第十三节），**一般不用再动 SSL/反代**。

详细运维说明：[deploy/server/README.md](./server/README.md)

```text
用户 → https://tp.textengine.cn (443，边缘反代 + SSL)
         → http://127.0.0.1:18080（本仓库 Docker）
```

若浏览器打开 tp 却是别的网站（例如清嘉录），说明 **443 反代尚未指向 18080**，按 11.2–11.3 处理，与 `git pull` 全唐诗无关。

### 11.1 SSL 证书（仅 tp 域名）

证书目录（与全唐诗数据盘并列，**不要**和别的项目混用路径）：

```bash
sudo mkdir -p /data/certs/tp.textengine.cn
```

签发（示例，按你机房习惯二选一）：

```bash
sudo apt-get install -y certbot
sudo certbot certonly --webroot -w /var/www/certbot -d tp.textengine.cn
# 或：sudo certbot certonly --nginx -d tp.textengine.cn
```

将证书放到：

```bash
sudo cp /etc/letsencrypt/live/tp.textengine.cn/fullchain.pem /data/certs/tp.textengine.cn/fullchain.pem
sudo cp /etc/letsencrypt/live/tp.textengine.cn/privkey.pem   /data/certs/tp.textengine.cn/privkey.pem
```

若有 **`*.textengine.cn` 通配符**，可指向同一 PEM，并编辑 `deploy/server/tp.textengine.cn.conf` 中的路径。

### 11.2 边缘反代（服务器管理员做一次）

```bash
sudo mkdir -p /data/nginx-sites
sudo cp /opt/quatangshi/deploy/server/tp.textengine.cn.conf /data/nginx-sites/tp.textengine.cn.conf
```

把该文件 **include 进当前监听 443 的 Nginx**（具体方式取决于你机器上谁占用了 443，本仓库不维护那份配置）。

- **推荐长远**：宿主机 Nginx 独占 443，参考 `deploy/server/edge-nginx.example.conf`。  
- 片段内 upstream 为 **`127.0.0.1:18080`**，无需 `host.docker.internal`。

改完后重载 Nginx，并确认全唐诗已启动：

```bash
curl -s http://127.0.0.1:18080/api/health
```

### 11.3 验收

```bash
curl -sI https://tp.textengine.cn | head -5
```

浏览器应出现「全唐诗 · 检索」，而非其他站点。

## 十三、日常更新（GitHub：先 push，再 pull）

### 在 Windows 开发机（改完代码后）

```powershell
cd "d:\Suzhou in Tang Poetry​"
git add -A
git status
git commit -m "说明本次修改"
git push origin main
```

### 在服务器（只更新全唐诗，不动别的项目）

**不要用 `nano` 改 `deploy/` 里的代码**；与 GitHub 不一致时，用下面「覆盖」恢复仓库版本。  
服务器上**唯一常改**的文件是 `deploy/.env.prod`（密码，不进 Git）。

```bash
cd /opt/quatangshi
git fetch origin main
git reset --hard origin/main
python3 tools/build_phase1_index.py
sudo docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod up -d --build
sudo docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod --profile bootstrap run --rm bootstrap
```

`git reset --hard` 会丢掉服务器上对仓库文件的手改，**不会删除** `deploy/.env.prod`（已在 `.gitignore`）。

仅改前端、未改语料时：可省略 `build_phase1_index.py` 与 `bootstrap`，只 `fetch` + `reset --hard` + `up -d --build`。

清单见 [`GIT-仓库与生产.md`](./GIT-仓库与生产.md)。

## 十四、常见问题

### 1. `git clone` / `git pull` 失败

先跑 **第五节 5.1** 三条测试，看卡在哪一步。常见现象：

| 现象 | 含义 |
|------|------|
| `curl` / `git ls-remote` 超时 | 服务器出网或 GitHub 暂不可达，**等网络恢复再试** |
| `GnuTLS recv error (-110)` | 同上，勿连续重试 |
| `git ls-remote` 成功但 `clone` 失败 | 先 `git config` 见 5.1，再清空目录后重 clone |

开发机需已 `git push`，服务器再 `git pull`。

### 2. `docker compose` 提示 command not found

试：

```bash
sudo docker compose version
```

若无输出，安装插件：

```bash
sudo apt-get install -y docker-compose-v2
```

### 2b. `ssh root@...` 提示 Permission denied

请改用 **`ssh ubuntu@43.142.176.9`**，本手册命令已按 ubuntu + `sudo` 编写。

### 3. Docker 构建 `pip install` 失败（exit code 2）

在服务器先 `git pull` 拿到最新 `deploy/Dockerfile.prod` 与 `deploy/requirements.api.prod.txt`，再：

```bash
cd /opt/quatangshi
ls deploy/requirements.api.prod.txt deploy/Dockerfile.prod
sudo docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod build --no-cache api
```

### 4. `build` 时提示找不到 `quatangshi_phase1.jsonl`

先执行第七节 `python3 tools/build_phase1_index.py`，再 `up -d --build`。

### 5. `curl 127.0.0.1:18080` 不通

```bash
sudo docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod logs --tail=50 api
sudo docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod logs --tail=50 web
```

常见原因：`.env.prod` 密码未改、构建未完成、内存不足。

### 6. 打开 `tp.textengine.cn` 却是别的网站

全唐诗容器可能正常，但 **443 反代未指向 18080**。先 `curl -s http://127.0.0.1:18080/api/health`，若为 ok，按 **第十一节** 配置 `deploy/server/tp.textengine.cn.conf` 与 SSL，**不要**在本仓库里寻找「清嘉录」相关文件名。

### 7. 内网健康但域名打不开

- DNS 是否指向 `43.142.176.9`  
- `deploy/server/tp.textengine.cn.conf` 是否已 include 并重载 Nginx  
- 证书路径是否与 `tp.textengine.cn.conf` 中一致（`/data/certs/tp.textengine.cn/`）  

### 8. 内存 4GB 构建失败

可临时加 swap（可选）：

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
```

构建完成后再 `swapoff /swapfile` 亦可保留。

### 9. 清嘉录与全唐诗会互相删数据吗？

不会。PostgreSQL 目录分别为 `/data/qjl/pgdata` 与 `/data/qts/pgdata`，互不影响。

## 附录 A：`deploy/Dockerfile.prod` 长什么样？（不用手改）

Docker 按「阶段」分块构建。国内镜像 **已写在文件里**，你只需 `git pull` 后执行第九节的 `docker compose ... build`。

**前端阶段**（编译 React，生成静态网页）——顺序从上到下：

```dockerfile
FROM node:22-bookworm-slim AS web-builder    # ← 第 1 步：选 Node 镜像
WORKDIR /app
RUN sed -i '...mirrors.aliyun.com...' \       # ← 第 2 步：换 Debian 源 + npm 国内镜像
    && npm config set registry https://registry.npmmirror.com
COPY apps/web/package.json ...               # ← 第 3 步：复制 package.json
RUN npm ci                                   # ← 第 4 步：安装依赖（在第 2 步之后）
COPY apps/web/ ./
RUN npm run build                            # ← 第 5 步：打出 dist/
```

**API 阶段**（Python 后端）：

```dockerfile
FROM python:3.12-slim-bookworm AS api
RUN sed -i '...mirrors.aliyun.com...' \       # ← 换 Debian 源，再 apt-get install curl
    && apt-get update && apt-get install ...
COPY deploy/requirements.api.prod.txt ...
RUN pip install ... -i https://pypi.tuna.tsinghua.edu.cn/simple ...
```

你**不需要**在服务器 `nano` 里插入 `RUN sed ...`：若本地 Windows 已改好并 `git push`，在服务器 `/opt/quatangshi` 执行 `git pull` 即可同步整份 `deploy/Dockerfile.prod`。

查看服务器上的文件是否最新：

```bash
grep -n "mirrors.aliyun" /opt/quatangshi/deploy/Dockerfile.prod
grep -n "requirements.api.prod" /opt/quatangshi/deploy/Dockerfile.prod
```

有输出则说明镜像配置已在位。
