# 01 — 项目概述与目标

## 1.1 项目名称与定位

- **仓库名**：Suzhou in Tang Poetry（唐诗中的苏州）
- **语料基础**：《全唐诗》（曹寅、彭定求等）数字化 **XHTML 正文**（约 900 卷）
- **工程定位**：以全唐诗为底本，建设**可校对、可检索、可扩展**的结构化语料与索引；并支持以 **苏州（及吴地相关地名、典故）** 为主题的筛选与分析（专题层，见需求文档）。

本项目**不是**电子书阅读器、**不是**通用古籍 OCR 平台；核心是 **语料治理 + 索引 + 数字人文查询**。

## 1.2 要解决的问题

1. **定位与引用**：从卷、篇题、作者快速找到原文（HTML + 索引）。
2. **批量检索**：按作者、体裁、关键词、地名（二期）查询。
3. **统计口径清晰**：区分「索引条」（篇题块）与「诗首」（组诗、乐府需展开）。
4. **可复核**：自动推断（分首、匹配地名）默认待人工确认，不冒充定稿。
5. **版式统一**：卷名、篇题、卷目导航与正文一致，减少解析噪音。

## 1.3 目标用户（设想）

| 角色 | 典型任务 |
|------|----------|
| 文献整理者 | 校对 HTML、统一篇题/卷名 |
| 研究者 | 检索、导出、苏州相关诗作统计 |
| 开发者 / Agent | 维护脚本、重建索引、扩展二期字段 |

## 1.4 成功标准（高层）

- Phase 1 索引与 900 卷 HTML **可追溯**（`source_file` + `id`）。
- 卷名、篇题规范率达标（见质量文档）。
- 全库诗首数量与通行说法（约 4.89 万首）**量级一致**（经二期展开或说明口径后）。
- 苏州子集可复现生成，并带匹配依据字段。
- 文档、脚本、数据路径一致；新成员仅读 `docs/` 即可理解架构。

## 1.5 明确不做（当前阶段）

- 不做面向公众的在线 Web 产品（可后续另立项）。
- 不大规模改写诗句正文（仅纠错式小改，且需有依据）。
- 不承诺一期内完成诗人年表、意象知识图谱等外源-heavy 功能。
- 不将 EPUB、电子书交付格式作为项目叙述重点（语料仅为 XHTML 文件集）。

## 1.6 与「全唐诗」的关系

- 正文：**全库** 900 卷，非节选。
- 专题：**苏州相关** 为派生视图，不替换全库索引。
- 版权与来源：须在 `12-未决问题` 中记录底本来源与使用范围（待填写）。
