# 04 — 需求说明

## 4.1 需求分层

| 层级 | 编号前缀 | 说明 |
|------|----------|------|
| **Must** | R-M | 一期维护与检索必备 |
| **Should** | R-S | 二期应做，影响研究体验 |
| **Could** | R-C | 增强项，资源允许再做 |
| **Won't（本期）** | R-W | 明确排除 |

## 4.2 功能需求

### 语料维护（R-M）

| ID | 需求 | 验收要点 |
|----|------|----------|
| R-M1 | 按卷编辑 XHTML，保留 class 语义 | 改动局限相关 `text*.html` |
| R-M2 | 卷名三处一致 | `<title>`、`<h1>`、`juanmu.xml` 对应 `<item>` |
| R-M3 | 篇题格式 `卷{N}_{序}【题名】` | 与同卷相邻篇题一致 |
| R-M4 | 改 HTML 后可一键重建 Phase 1 | `build_phase1_index.py` 成功、条数合理 |
| R-M5 | 解析异常可筛查 | `parse_note` 非空可导出列表 |

### 检索与查询（R-M / R-S）

| ID | 需求 | 阶段 | 验收要点 |
|----|------|------|----------|
| R-M6 | 按作者、卷名、篇题片段查询 | P1 | SQLite 或 JSONL 查询即可 |
| R-S1 | 正文关键词全文检索 | P2b | **Meilisearch** 自建（见 docs/13） |
| R-S2 | 按「诗首」浏览与计数 | P2a | 子表/子 JSONL，带 `parent_id` |
| R-S3 | 苏州（及吴地）相关诗作子集 | P2b | 可重建的 `suzhou_*` 索引 + 匹配词 |

### 分首与组诗（R-S）

| ID | 需求 | 验收要点 |
|----|------|----------|
| R-S4 | 「N 首」可展开为 N 条子记录 | 不删除 Phase 1 父记录 |
| R-S5 | 自动分首默认 `split_note=needs_review` | 含高置信规则拆 |
| R-S6 | 支持文献分首表（如帝京篇 9×4+8） | `tools/split_plans/*.json` 可配置 |

### 质量与治理（R-S / R-C）

| ID | 需求 | 阶段 |
|----|------|------|
| R-S7 | `validate_corpus.py` 门禁 | juanmu↔HTML、篇题规范、残留 `卷_` |
| R-C1 | 分首人工复核界面 | 可仅为 CSV 工作流，非必须 Web |
| R-C2 | 导出 Excel/CSV 供论文附录 | 二期 |

## 4.3 用户场景（User Stories）

1. **作为整理者**，我改正一卷篇题后，希望运行一条命令更新索引，而不用手改 JSONL。
2. **作为研究者**，我想查「刘长卿 + 苏州」相关作品，并得到篇题、全文、出处文件。
3. **作为研究者**，我想知道「全库有多少首诗」，且文档解释与 4.89 万的关系。
4. **作为开发者**，我想新增「分首规则」而不改动 HTML 源文件。
5. **作为审阅者**，我想看到自动分首结果但明确区分「未人工确认」。

## 4.4 非功能需求

| 类别 | 要求 |
|------|------|
| **可复现** | 索引可由 HTML + 脚本完全重建 |
| **可追溯** | 每条记录有 `source_file`、`id`；二期子记录有 `parent_id` |
| **可差分** | 语料改动小步提交，避免一次性万行 diff |
| **性能** | 全库重建索引 < 5 分钟（当前约 1–2 秒级，保持） |
| **便携** | 标准库优先，便于无网络环境 |

## 4.5 优先级建议（供拍板）

**第一批开发（审阅通过后）**

1. `validate_corpus.py`
2. Phase 2a 最小版：`expand_n_shou_phase2.py`（均匀 N 首 + split_plans）
3. Phase 2b：Meilisearch 全文检索 + `suzhou` 子集

**第二批**

- 分首复核工作流、导出工具、意象/年表（外源）
