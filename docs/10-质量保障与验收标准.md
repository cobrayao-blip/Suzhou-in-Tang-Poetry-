# 10 — 质量保障与验收标准

## 10.1 质量目标

| 层级 | 目标 |
|------|------|
| **一致性** | HTML、juanmu、索引三者卷名/篇题可对应 |
| **完整性** | 900 卷均有索引条；无批量断链 |
| **可解释性** | 自动推断均有 note/confidence |
| **可恢复** | 索引可从零重建且条数稳定 |

## 10.2 自动检查项（`validate_corpus.py` 规划）

| 检查 ID | 内容 | 严重级 |
|---------|------|--------|
| V1 | juanmu 每条 `href` 存在 | 错误 |
| V2 | juanmu 卷名 = HTML title/h1 | 错误 |
| V3 | HTML 中残留 `卷_\d+【` | 警告 |
| V4 | 篇题不含 `卷\d+_\d+【` 模式的比例异常 | 警告 |
| V5 | Phase 1 条数在 41 000±500（可配置） | 警告 |
| V6 | `parse_note` 非空条数趋势 | 信息 |

退出码：`0` = 无错误；`1` = 存在错误级项。

## 10.3 Phase 1 发布验收

- [ ] `build_phase1_index.py` 无报错完成
- [ ] `validate_corpus.py` 无错误级项（实现后）
- [ ] 随机抽 10 卷：篇题、作者、首句与 HTML 一致
- [ ] `parse_note` 清单已导出供人工排期

## 10.4 Phase 2a 验收（规划）

- [ ] 帝京篇十首：10 子记录，句数 `[4]×9+[8]`
- [ ] 芙蓉楼送辛渐二首：2 子记录，各 4 句
- [ ] 所有子记录默认 `split_note=needs_review`
- [ ] 父记录 `parent_id` 可反查

## 10.5 Phase 2b 验收（规划）

- [ ] Meilisearch：`query_meilisearch.py 姑苏` 返回预期名篇
- [ ] 苏州子集条数与手工抽检一致量级（~数百首，非精确硬指标）
- [ ] 子集每条含 `match_terms`

## 10.6 人工抽检建议

| 频率 | 内容 |
|------|------|
| 每改 10 卷 | 抽 1 卷全文对照索引 |
| 每期发布 | 抽 5 卷 + 全部 `parse_note` 清单过一遍 |
| 分首复核 | 优先「N 首」+ 高引用名篇 |

## 10.7 回归基准

记录每次发布时的：

- 索引条数
- `parse_note` 分布
- 重建耗时

写入 `docs/12-未决问题与决策记录.md` 的发布日志小节（实施时追加）。
